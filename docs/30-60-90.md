# 30 / 60 / 90-day plan for the client team

For the hotel group's IT lead and operations manager taking over both apps. Each step has an owner role and a way to
know it is done.

## Days 1–30: run it as it is

| Step | Owner | Done when |
|---|---|---|
| Walk through this package with the builder (recorded walkthrough + Q&A) | IT lead | questions logged and answered |
| Take over accounts: GitHub repos, Streamlit Cloud, Neon, Anthropic Console | IT lead | the client owns every account; builder access removed |
| [Rotate every secret](RUNBOOKS.md#6-rotating-secrets) after the handover | IT lead | Admin pages show all secrets **set**; old key deleted |
| Set the Anthropic **monthly spending limit** | IT lead | limit visible in the Console |
| Add `HEALTH_DATABASE_URL` to this repo's Actions secrets | IT lead | the daily Health check reports 24-hour error counts |
| Give staff the [assistant](STAFF_GUIDE_ASSISTANT.md) and [agent](STAFF_GUIDE_AGENT.md) guides | Ops manager | 5 staff have used each app once |
| Weekly Operations-page review | Ops manager | 4 reviews done; no open staff reports older than a week |

## Days 31–60: make it theirs

| Step | Owner | Done when |
|---|---|---|
| Replace the synthetic documents with the real policy documents ([runbook 8](RUNBOOKS.md#8-adding-a-new-propertys-documents)) | Ops manager + IT | eval re-run on 30+ real questions, strict retrieval ≥ 90% |
| Write 30 real staff questions and 15 real (anonymised) emails as held-out cases | Ops manager | added to the harness, run once, results reviewed |
| Put both apps behind the group's SSO (OIDC) with Staff and Owner groups | IT lead | shared passwords removed |
| Move to always-on hosting with the Docker images | IT lead | apps no longer sleep; uptime checked every minute |
| Agree retention and backups with the data protection lead | IT lead | `RETENTION_DAYS` and Neon backup settings match policy |

## Days 61–90: improve with evidence

| Step | Owner | Done when |
|---|---|---|
| Measure the pilot KPIs from the business cases (time per question/email, escalations caught) | Ops manager | before/after table from real logs, not projections |
| A second human labeler for answer quality; only then consider an LLM judge (kappa ≥ 0.6) | Ops manager | two labelers' agreement reported |
| Decide: expand to more properties, or stop | Ops manager + GM | go / no-go recorded against the KPIs |
| Monthly fresh-question eval run in CI | IT lead | first monthly run green and saved |
